# 커리어 글

프로젝트 하나가 끝나면 네 단계를 거친다. 1~3단계가 결정설명 티켓(`career-decision`), 4단계가 글 티켓(이 스킬)이다. 결정설명을 끝내지 않아도 글을 시작할 수 있다 — 언제 할지는 jw가 정한다.

**jw가 직접 부를 때만 쓴다.** 재료가 되는 작업 티켓이 남아 있어도 진행한다 — 남은 티켓 목록을 보여 주기만 하고 멈추지 않는다.

**글은 jw가 쓴다.** Claude는 질문하고, 초안의 틀린 숫자와 빠진 근거만 짚는다. 고친 문장을 내밀지 않는다. dev-workflow·orch·plan 문서를 쓰지 않는다.

## 부르는 법

**그 프로젝트 세션에서 이어서 부른다.** 작업 티켓을 처리하던 세션이 맥락을 가장 많이 들고 있다. 새 세션을 따로 열지 않는다.

인자 없이 `/career-writing`만 부른다. 프로젝트는 지금 레포로 정하고, 노션에서 그 프로젝트의 글 티켓을 찾는다.

- 없으면 §A로 만든다
- 있으면 §B 시작 → §C 진행. 멈췄던 단계부터 잇는다

글 티켓은 프로젝트마다 하나다. 그 프로젝트 전체를 다루는 글이다.

#178은 커리어 세션 아래 새 세션으로 열었다. 프로젝트가 여럿 동시에 끝나 이직 준비로 묶어 다룬 예외다.

## §A 티켓 만들기

1. 노션 프로젝트 진행 DB(data source `29241e61-65c0-80e4-aaf5-000bcafbb440`)에서 재료가 될 작업 티켓을 jw와 정한다. 그중 남은 티켓(상태가 `완료`가 아닌 것)이 있으면 목록을 보여 주고, 그대로 만들지 jw에게 한 번 묻는다
2. 그 프로젝트의 글 티켓이 이미 있으면 만들지 않고 그 번호를 알린다
3. 아래 프로퍼티와 본문으로 만든다. 호출은 `"$HOME/.claude/tools/notion-api/notion-api"`, payload는 python으로 파일을 만들어 넘긴다

| 프로퍼티 | 값 |
| --- | --- |
| 태스크 | `{프로젝트명} 글`. 부제는 §C 1단계에서 정해지면 `— {부제}`로 붙인다 |
| 상태 | `시작 전` |
| 프로젝트 | `커리어` |
| 선행 작업 | 재료 티켓 중 가장 늦게 끝나는 것 |
| 아이콘 | `https://www.notion.so/icons/document_gray.svg` (external) |

본문 서식은 `rules/apis.md` §페이지 작성 포맷(h2만, `yellow_background`, 첫 h2를 뺀 h2 앞에 빈 문단). 절은 아래 순서다. 예시는 #178(`40d41e61-65c0-8180-8ae3-d6bda5662bbb`).

- **배경**: 어느 프로젝트의 무엇을 보여 주는 글인지, jw가 직접 쓰므로 커리어 티켓이라는 것
- **jw 기준**: 비워 둔다. 「착수할 때 jw에게 받는다」 한 줄만 적는다
- **재료**: 재료 티켓 번호와 그 결과, 그 레포 `docs/decisions.md`
- **작업 위치**: 레포 절대 경로, 게시처(포트폴리오 페이지 `7cbf8a03a9d347a7bda8a0e62c781cfb`, #114 — jw가 다른 곳을 말하면 그것), 「그 프로젝트 세션에서 이어서 한다」, 「이 스킬로 진행한다: `/career-writing`」 한 줄
- **통과 기준**: 글이 답해야 할 질문과 들어가야 할 실제 사례, 레포 README와 게시처에서 링크가 걸린다
- **이번에 안 하는 것**: 새 측정. 이미 저장된 결과 숫자만 쓴다
- **실패 징후**: 원인을 설명하지 못한 사례가 남아 있다 / Claude가 쓴 문단이 남아 있다

## §B 시작

1. 노션 티켓 본문을 읽는다. 남은 재료 티켓이 있으면 목록만 보여 주고 진행한다
2. 노션 `상태`를 `진행 중`, `작업일` start를 오늘로 바꾼다

## §C 진행

1. **jw 기준 한 줄** — 「이 글을 읽은 사람이 무엇을 알게 되면 성공인가」를 jw에게 받아 원문 그대로 노션 `jw 기준` 절에 적는다. Claude가 잴 수 있게 옮긴 문장은 `(Claude가 옮김)`을 붙여 따로 적는다. 다시 쓰라고 내밀지 않는다. 태스크 이름에 부제가 없으면 이때 jw에게 부제를 받아 붙인다
2. **재료 범위** — 어느 티켓의 어느 숫자를 쓸지 jw와 정한다. 같은 값이 리포트마다 다르면(정규화를 바꿔 다시 센 경우 등) 어느 기준으로 쓸지 jw가 고른다
3. **재료 모으기** — 레포 `docs/` 아래에 재료 문서를 만든다(예: `/Users/jw/prv/cheongyak-extract/docs/decision-source.md`)
   - 절마다 사실과 출처(리포트 파일·칸)만 적는다. 숫자에는 세는 방법과 비교 대상을 붙인다
   - 「고른 방식과 이유 (jw)」 칸은 비워 둔다
4. **뼈대** — jw가 절 순서를 쓴다. Claude는 jw 기준에 답하는 절이 빠졌는지만 짚는다
5. **초안** — jw가 쓴다. Claude가 짚는 것은 넷이다
   - 재료 문서와 다른 숫자
   - 근거 없이 쓴 주장
   - 사건 순서가 실제와 다르게 읽히는 곳
   - jw 기준 중 글에 없는 쪽
6. **게시** — jw가 게시처에 올리고, 레포 README에 링크를 건다. 커밋은 jw가 하라고 할 때만 한다(`docs:` 접두사, 한글)

멈췄다 다시 시작하면 노션 티켓 본문에 「어디까지 했나」를 단계 번호로 적어 둔다.
