# HR Review Prep (셀프 리뷰 / 피어 리뷰)

반기(26H1, 26H2 …) 리뷰&리워드 시즌마다 셀프 리뷰 + 피어 리뷰를 작성하는 방법론.
증거는 **Jira·Slack·과거 Notion 메모**에서 뽑고, 사실에 근거해 초안을 만든 뒤 개인 Notion 페이지에 채운다.

## 언제 쓰나
- Slack에 `리뷰&리워드 공지`가 뜨고 셀프/피어 리뷰 작성 기간이 시작될 때
- 사용자가 "셀프리뷰/피어리뷰 준비" 요청할 때

## 호출 방법 (Args)
고정 파라미터는 없다. `/hr-review` 뒤에 **시즌 + 링크 4종 + 기간**을 메시지로 붙인다(과거 메모는 선택).

```
/hr-review 26H2
- 계획: <리뷰&리워드 계획 Notion url>
- 셀프 템플릿: <셀프 리뷰 Notion url>
- 피어 폼: <피어 리뷰 Notion url>            # Tally embed면 WebFetch로 문항 추출
- 리뷰어 공지: <Slack "리뷰어 선정" 링크 or 캡처>   # 작성 대상자
- 과거 메모: <직전 시즌 메모 url>, <그 이전 url>   # 선택, 연속성 강화
- 기간: 2026-07-01 ~ 2026-12-31              # 회사 반기 정의 확인
```

최소 입력 = **시즌 + 계획/셀프/피어/공지 링크 + 기간**.
링크 일부가 없으면: 캡처를 붙이거나(리뷰어 공지·피어 문항), 스킬이 fetch 시도 후 404면 integration 공유를 요청한다.

## 필요한 입력 (사용자에게 받거나 확인)
1. **시즌 문서 3종** (Notion): 리뷰&리워드 계획 / 셀프 리뷰 템플릿 / 피어 리뷰 폼(보통 Tally embed)
2. **리뷰어 선정 공지** (Slack): 내 피어 리뷰 **작성 대상자** — 상호선택 + 내가선택 + 나를선택(질문 필요: 나를선택도 작성 대상인지 확인). 이번 정책은 4명 전원 작성이었음.
3. **과거 리뷰 메모** (Notion, 지난 시즌들): 연속성 참조용
4. **반기 기간**: 예) 26H1 = 2026-01-01 ~ 2026-06-30 (회사 정의 확인 — Q2를 7월까지 잡기도 함)

> ⚠️ Notion API로 읽으려면 각 페이지를 integration(`dify`, `PLAB_NOTION_API_KEY`)에 **Connections 공유**해야 함. 404 나면 공유 요청.

---

## Phase 1 — Kickoff
- 시즌 문서 3종 fetch → 셀프 템플릿의 **테이블 컬럼 구조** + 섹션, 피어 폼 문항 파악.
  - 피어 폼이 Tally embed면 Notion엔 문항 없음 → `WebFetch`로 Tally URL 열어 문항 추출.
- 리뷰어 확정 (작성 대상자). Slack user ID 해석해 둠.

## Phase 2 — 셀프 리뷰
셀프 템플릿 구조(예): §1 결과/성과 테이블, §2 성과를 만든 과정(강점/아쉬운), §3 리더와 논의.

1. **Jira 집계** — 반기 내 내 티켓:
   ```
   assignee = currentUser() AND created >= "<시작>" AND created <= "<끝>" ORDER BY created
   ```
   - 100+개면 Epic(parent)별로 뭉쳐 **대형 프로젝트 축** 도출. `approximate-count` 엔드포인트로 테마별 카운트.
   - 엔드포인트: `/rest/api/3/search/jql` (deprecated `/search` 금지). `-u jongwoo.kim@plabfootball.com:$JIRA_API_TOKEN | jq` (RTK bypass).
2. **§1 테이블** — 컬럼: 주요 프로젝트(분기/소속팀) / 당초 목표 / **결과(Result=목표 달성 '사실')** / **성과(Impact=조직에 만든 '변화·기여')** / 업무 비중(%) / 참고 / 비고.
   - **결과 ≠ 성과** 를 반드시 구분. 회고가 "결과"까지라면 셀프리뷰는 "그래서 조직에 뭐가 바뀌었나"를 추가.
   - **비중**: 티켓 수는 심하게 왜곡됨(인프라 1건=수주, CS 1건=수시간). 티켓 수 + 실제 투입기간 블렌딩. 보여줄 가치 큰 코어에 가중.
   - 분기(Q1/Q2)는 티켓 created 월 기준.
3. **§2** 강점/아쉬운 — 실제 사건 기반, 정직하게(성과·실패 모두). **§3** 리더 논의.
4. 개인 Notion 페이지(템플릿 복제본)에 append. 테이블은 `table` 블록 + `table_row` children 한 번에 생성.

## Phase 3 — 피어 리뷰
피어 폼(예): 정량 0~5+SKIP 5축(**책임·소통·결정** = 함께 일하는 태도 / **동료돕기·신뢰** = 팀 기여) + 리더 대상 3축(팀성과·수평소통·성장지원) + 정성 서술 3개(⑪ 인상적 / ⑫ 성장 제안 / ⑬ 자유). **정성=실명, 정량=익명.**

1. **리뷰어 Slack ID 해석** — `users.list` 페이지네이션 + grep. (제어문자 파싱 에러나면 `tr -d '\000-\037'` 로 sanitize.)
2. **증거 수집 (반기로 시간 필터 필수)**:
   - **DM**: `conversations.open` → `conversations.history`. ⚠️ `limit=80`은 **개수**지 시간 필터가 아님 → 반드시 `ts >= <반기시작 epoch>` 로 걸러 옛날 사건 배제.
   - **채널**: `search.messages` (user token 필요) `query="from:<@UID> in:<#CHANNEL> after:2026-01-01"`, permalink·ts 확보.
   - 프로젝트 채널(예: 플랩2.0)까지 훑어 활동 파악.
3. **과거 메모** — 지난 시즌 메모의 이름별 nested 내용까지 읽어 **연속성** 확보("사람은 크게 안 변함"). 강점은 "한결같다", 성장은 "예전보다 나아졌다"로.
4. **작성 (인당)**:
   - 정성 ⑪⑫⑬ — **직접 함께 일한 경험** 중심. 피어 리뷰 취지 = "이 동료와 함께 일한 경험". 채널서 *관찰만* 한 건 취지 약함 → 빼거나 "옆에서 본"으로 솔직히.
   - 정량 — 정성 근거 기반, 인플레 지양. 직접 근거 얇은 축은 **SKIP(0)**.
   - 리더 대상자면 리더 3축도.
5. 개인 메모 Notion 페이지에 append.

## 품질 규칙 (이 방법론의 핵심)
- **시간 경계**: 모든 증거를 반기 안으로. DM 개수 필터 ≠ 시간 필터. 인용 전 날짜 확인.
- **결과 vs 성과** 구분. 성과 = 조직에 만든 실질 변화.
- **직접 경험 vs 관찰** 구분(피어). "함께 일한" 것만이 취지에 부합.
- **사실 태깅**: 검토 시 문장을 [사실]/[해석: 평가어]/[제안: 내 의견]/[과거메모: 지난 시즌 주관] 으로 나눠 검증. 팩트 아닌 곳이 위험지점.
- **정량 인플레 지양**: 4~5는 "안심하고 맡김" 확실할 때. 근거 없으면 SKIP.
- **비중 산정 근거 명시**: 티켓 수 왜곡 경고 + 블렌딩 방식 설명.

## 스타일 규칙
- **쉬운 말 우선** — 딱딱한 한자어 지양(규명→밝혀낸, 수용→받아들이는). 상대가 안 쓰는 표현 피하기.
- **동등한 동료 톤** — "믿고 맡길 수 있다"(상사 어투) 대신 "함께 일하면 든든했다"(동료 시점).
- **주어/목적어 챙기기** — "막힘 없이 진행됐어요" → "제 작업도 막힘 없이 이어졌어요".
- **연속성은 강점에만** 얹는 옵션(성장축까지 얹으면 평가자 톤 남).
- 문서 컨벤션: 본문 구분자 `·` → `, `(콤마+공백). 정량 점수 라인의 `·`는 유지.

## 보안 규칙 (필수)
DM/채널에 **라이브 시크릿**(API key, AWS 키, DB 비번, .env 덤프, Slack 토큰 등)이 자주 노출됨.
- 절대 어디에도 **저장·전파·에코 금지**. 스크립트 출력 시 redact: `sed -E 's/(sk-ant-[A-Za-z0-9_-]+|ntn_[A-Za-z0-9]+|xox[baprs]-[A-Za-z0-9-]+|AKIA[A-Z0-9]{16}|[A-Fa-f0-9]{32,})/[REDACTED]/g'`
- 발견 시 사용자에게 **로테이션/폐기 경고**.

## 툴링 노트 (겪은 함정)
- Notion: 페이지가 integration에 미공유면 404 → 공유 요청. 표 셀 수정은 `table_row` 전체 cells 재전송(부분 patch 불가).
- Notion 표 셀에 개행 넣으면(예: 프로젝트명 아래 분기), 읽어와 bash `echo|jq` 라운드트립 시 제어문자 에러 → **파일 기반 jq**(`jq ... > f.json; curl --data @f.json`)로 처리. 셀 편집 시 개행 rich_text 요소 **유실 주의**(재부착 필요).
- Notion 중첩 블록: 사용자가 내용을 템플릿 구조 하위로 옮기면 top-level 스캔이 놓침 → 하위 children까지 재귀 확인.
- `·`→`,` 치환은 `gsub("\\s*·\\s*"; ", ")` (주변 공백 정리).
- Jira: `approximate-count` 로 테마별 카운트 빠르게. 순차 curl 많으면 타임아웃 → 배치/타깃.
- Slack: `search.messages`는 user token. `users.list` 제어문자는 `tr -d '\000-\037'`.

## 진행 원칙
- 각 단계 산출물은 **채팅에서 먼저 보여주고 사용자 검토** 후 Notion 반영. 팀 페이지/개인 페이지 write는 사용자 확인 후.
- 사실 검증 요청이 오면 문장→출처(채널/DM 날짜, permalink, 티켓) 매핑표로 근거 제시.
