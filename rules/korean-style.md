# 한국어 표현 규칙

한국어로 답할 때 적용. 코드·커밋 메시지·영문 문서는 해당 없음.

## 원칙

**짧게 쓰려고 새 단어를 만들지 않는다.** 모르는 단어는 짧아도 느리다 —
읽는 쪽이 멈춰서 뜻을 추측해야 하면 압축이 아니라 손실이다.

**Why:** 영어로 개념을 잡고 한국어로 옮기면 한자어를 조립해 조어를 만들게
된다. 만든 쪽은 뜻이 명확하니 계속 재사용하고, 문서와 다음 세션에 그대로
번져 굳는다.

2026-08-13 실측으로 원인을 좁혔다. 조어가 처음 나타난 시점(`임계선` 7-16,
`실격선` 7-30)은 영어로 개념이 잡히는 작업(RAG 설계, portfolio-judgment)이
시작된 때와 붙는다. 전부 영어 원어가 먼저 있고 거기 한자를 갖다 붙인
형태다 — `retrieval`→`회수`, `disqualification threshold`→`실격선`,
`fired`→`발화`, `wiring`→`배선`. **압축이 아니라 번역이 원인이다.**

## 규칙 파일에 있다고 사용자 어휘가 아니다

**여기서 이상하게 읽히는 말은 거의 전부 Claude가 만든 것이다.** 사용자가
직접 도입한 기술 용어는 드물다.

내가 쓴 말이 규칙 파일로 승격된 사례가 있다 — `불통과 신호`·`의도적 비목표`는
2026-07-27 내가 처음 쓰고 다음 날 `portfolio-judgment.md`에 편입됐다. 그 뒤
`rules/` 2개 + `skills/` 2개, 총 8곳으로 번졌고 `rules/`는 매 세션 자동
로드되므로 **내가 그 말을 다시 보고 다시 쓰는 회로**가 됐다. 2026-08-13에
전부 교체했다 (아래 표).

`rules/`에 있다는 이유로 "합의된 용어"라고 단정하지 말 것. 확인하려면 대화
기록에서 **누가 먼저 썼는지**를 본다 — git author는 증거가 아니다 (Claude가
대신 커밋해도 사용자 이름이 찍힌다).

**규칙 파일에 굳었다는 것은 유지할 이유가 아니라 고칠 이유다.** 치환은 한 번에
끝나지만 방치하면 매 세션 재주입된다.

### 사용자가 그 말을 썼다는 것도 증거가 아니다

2026-08-14에 이걸로 오판했다. `수확`(harvest 직역)을 교정 대상에서 뺐는데, 근거가
*"jw 가 직접 썼다 — 백로그 수확 마저 진행해줘"* 였다. 사용자 답: **"수확은 클로드가
말한 건데 그냥 내가 이어서 쓴거야."**

대화에서 사용자가 쓴 것을 보는 것만으로는 부족하다. **누가 먼저 썼는지**를 봐야 한다.
이어서 쓴 것은 동의가 아니라 그 자리에서 되묻지 않은 것뿐이다 — 대화를 멈추고 용어를
따지는 비용이 그냥 따라 쓰는 비용보다 크다.

내가 만든 말이 대화에 한 번 들어가면 사용자 입에서 돌아 나오고, 그러면 내가 그것을
"합의된 말"로 재분류한다. 규칙 파일 승격 회로와 같은 구조인데 한 단계 더 짧다.
**의심스러우면 유지 근거를 찾지 말고 물어라** — 위 대화도 "어떤 걸로 바꾸는 게
좋겠어?" 한 줄로 끝났다.

### plan 문서가 `rules/` 다음으로 센 재주입 회로다

`rules/`는 매 세션 자동 로드되니 위험이 눈에 보인다. `docs/plans/*.md`는 안 보이는데
경로가 같다 — 다음 세션이 착수할 때 읽고, 거기 있는 말을 그대로 코드 주석과 테스트에
옮긴다.

2026-08-20 `pf-policy-bot` 실측. `시임`(seam 음차)이 `DEV-6833-0720-plan-db-cache-alarm.md`
에서 처음 나와 **10개 파일 30곳 + 커밋 메시지 3개**로 번졌다. 경로는
plan → 코드 주석 → 테스트 docstring → 이후 plan 3개다. 같은 repo에 이미 교정 표에
있던 `배선` 55곳, `비질문` 59곳도 같은 식으로 남아 있었다 — 표에 넣은 날 채팅에서만
고쳤고 repo는 안 봤기 때문이다.

**표에 추가할 때 그 말이 이미 나간 repo를 같이 grep한다.** 한 번에 끝나는 일이고,
안 하면 plan을 읽는 다음 세션이 매번 되살린다.

#### grep은 **한 repo가 아니라 전부**다

2026-08-21에 이 지시를 반쪽만 지킨 것이 드러났다. 채팅에서 `Slack 배선`이라고 써서
지적받고 확인해 보니:

| 곳 | 배선 |
| --- | --- |
| `pf-policy-bot` — 위 표를 쓴 그 repo | **0** (정리 끝남) |
| `social-backend-fastapi` | 178 |
| `new-plab-front` | 122 |
| `plaby` · `jobs` · 기타 | 24 |

**표에 적힌 55곳은 고쳐졌고, 한 번도 안 본 repo에 그 6배가 남아 있었다.** 전부 wiring
직역이다 (`주입 배선` `훅 배선` `방어 배선` `onComplete→닫기 배선`). 전기 배선 원뜻은 0건.

위치도 그대로 이 절이 말한 재주입 경로다 — `docs/sot/changes/*.md`,
`docs/superpowers/plans/*.md`, 거기서 옮겨간 코드 주석과 테스트 docstring.

`~/plab`은 16개 repo를 담은 dispatch root라 **한 repo를 고치는 것은 표본이지 처리가
아니다.** 걸린 말이 나온 repo만 보지 말고 `~/plab` 전체를 센다:

```bash
cd ~/plab && for d in */; do n=$(grep -rn "<말>" "$d" 2>/dev/null | wc -l | tr -d ' ')
  [ "$n" -gt 0 ] && echo "$n  $d"; done | sort -rn
```

**회사 repo는 세는 것과 고치는 것을 분리한다.** 300곳 치환은 PR 여러 개에 배포 부담이
붙는 일이라 이 규칙이 시킬 수 있는 범위를 넘는다. 숫자는 여기 적어 두고, 치환은 티켓으로
따로 잡거나 그 파일을 어차피 건드릴 때 같이 고친다. **`~/.claude`는 내 것이니 즉시 고친다.**

## 위험 지대는 판단·평가 어휘만이 아니다

**표본이 둘이고 서로 다르게 나온다. 어느 쪽에서 잰 것인지 보고 읽을 것.**

### 프로브 12문항 (2026-08-13) — 기술 용어는 안전했다

새 기술 개념은 **원어를 그대로 썼다** — `backpressure`, `idempotency key`,
`DLQ`, `bulkhead`. 정착 번역어가 없으면 만들지 않는다. 이 영역에서는 조어가
안 나왔다.

### repo 전수 (2026-08-20, `pf-policy-bot` 194곳) — 정확히 반대로 나왔다

걸린 것이 전부 기술 용어다. 판단·평가 어휘는 **한 건도 없었다.**

| 걸린 말 | 원어 | 곳 |
| --- | --- | --- |
| 비질문 | non-question | 59 |
| 배선 | wiring | 55 |  <!-- 이 repo는 이후 0건. 다른 repo에 324곳 — 위 「grep은 한 repo가 아니라 전부다」 -->
| 단언 | assertion | 30 |
| 시임 | seam | 30 |
| 뮤테이션 | mutation | 12 |
| 발화 | utterance | 7 |
| 회수 | recall | 1 |

**「이 영역에서는 조어가 안 나온다」는 문장은 이 실측으로 뒤집혔다.** 기술 용어라고
안전하지 않다.

**왜 어떤 기술 용어만 번역되는지는 이 데이터로 못 가른다.** `bulkhead`는 `격벽`이
사전에 있는데도 원어로 뒀고 `seam`은 음차했다 — 둘 다 비유이고 둘 다 한자어 후보가
있다. 빈도 차이로 설명하려면 압축이 원인이라는 뜻이 되는데 그건 위 프로브에서 이미
반대로 측정됐다(`full` 2.07 < `lite` 5.57). **가설을 세우지 말고 걸린 것을 표에
넣는다.**

### 판단·평가 어휘 (프로브에서 관측)

조어는 **판단·평가를 서술할 때도** 나온다. `disqualification threshold`를
`실격선`으로, `go/no-go`를 `통과선`으로 옮기려 한다 — 이쪽은 기술 용어가
아니라 "번역해야 할 일상어"로 분류하기 때문이다. 같은 실측에서 규칙을 뺀
대조군은 이 영역에서만 조어를 냈다(`통과선`).

**통과·탈락·기준·신호·판정을 서술하는 문장에서 특히 멈출 것.**

이 영역이 위험하다는 것 자체는 안 뒤집혔다. repo 전수에서 `실격선`·`통과선`·
`임계선`이 0건이었던 것은 안전해서가 아니라 **그 repo에 그런 문장이 없어서**다
(RAG·포트폴리오 쪽 어휘다). 표본이 그쪽을 재지 못했다.

| 임계선 | **임계값**, **기준** | 같은 계열 |

| 시임 *(seam)* | **`seam`** 원어 그대로 | 음차. 한국어로 뜻이 안 잡히고 사전에도 없다. 정착 번역어가 없으니 만들지 않는다 (아래 「그대로 써도 되는 것」 원칙). 2026-08-20 지적 |

회수되면"* ✗.

### 패턴 — `비-`로 부정을 조립하지 말 것

`X선`과 같은 자리의 문제다. 영어 `non-`·`is_x=False`를 한 글자로 접으려다
나온다 — `non-question`→`비질문`, 그 전에는 `의도적 비목표`가 같은 식이었다.

한국어에 정착한 `비-`는 `비공개`·`비정상`처럼 **뒤에 오는 말이 이미 한자어
한 덩어리**일 때뿐이다. `질문`처럼 그 자체로 완결된 명사 앞에 붙이면 사전에
없는 말이 된다.

```
✗ 플래너의 비질문 오분류를 제외한다
✓ 플래너가 질문이 아니라고 잘못 분류한 케이스를 제외한다
```

풀어 쓰면 길어지지만 한 번에 읽힌다. **코드 식별자(`is_question`,
`non_question_runs`)는 그대로 둔다** — 번역해야 할 대상이 아니다.

### 패턴 — `X선`으로 기준을 만들지 말 것

개별 단어를 하나씩 막는 것보다 이쪽이 넓다. 2026-08-13 대조군 20문항에서
`임계선`·`합격선`·`상대선`·`절대선`·`경계선` **5종**이 나왔다. 규칙을 넣은
쪽에서는 0종. 같은 프롬프트에서 이렇게 갈렸다:

```
✗ 절대선 대신 baseline 대비 상대선 …  선은 eval셋 만들 때 같이 정함
✓ 임계값은 실패 비용에서 역산한다 …  precision은 recall 통과 후 2차 기준
```

기준을 뜻하는 `선`은 `마지노선` 정도만 정착돼 있다. **`X 기준`,
`임계값`으로 쓴다.** 아직 안 만든 `X선`도 만들지 않는다.

**긴 글에서는 이 규칙이 덜 듣는다.** 같은 날 24문항을 10~15줄 분량으로
다시 재니 규칙을 넣고도 `경계선`이 새어나왔다 — *"그게 경계선이다"*.
1만자당 대조군 3.0 → 적용군 0.78로 줄긴 했으나 0은 아니다. 4줄짜리
답변에서는 0이었다. 문서를 길게 쓸수록 한 번 더 멈출 것:

```
✗ 최적화가 구조를 무너뜨리기 시작하면 그게 경계선이다
✓ 최적화가 구조를 무너뜨리기 시작하면 거기서 멈춘다
```

## 남의 분야 용어를 끌어오지 말 것

원어를 그대로 두는 것과 **다른 분야 전문용어를 수입하는 것은 다르다.**
아래 「그대로 써도 되는 것」과 헷갈리기 쉬워 따로 적는다.

| 원어 유지 ○ | 끌어오지 말 것 ✗ |
| --- | --- |
| `backpressure` `idempotency` `DLQ` `props` | `arm` `cohort` `ablation` |
| 읽는 사람이 그 분야에서 일한다. 그게 그 바닥의 이름이고 번역하면 뜻이 흐려진다 | 정밀하다는 이유로 남의 분야에서 가져왔다. **한국어에 이미 말이 있다** |

| 쓰지 말 것 | 대신 |
| --- | --- |
| arm *(실험군/대조군의 각 집단)* | **대조군**, **적용군** |
| arm *(잡·기능을 켜는 것)* | **켬**, **가동** |
| 율속 *(rate-determining step, 화학 용어)* | **병목**, **제약 요인** | 2026-08-24 지적 |

2026-08-13에 실제로 저질렀다 — 조어를 논의하는 대화 안에서 `규칙 arm`이라고

## 번역투는 조어와 다른 문제다

2026-08-23 실측. Addy Osmani 키노트를 요약해 Notion Dev Scraps에 넣었는데
**조어는 0건**이었다 — 위 교정 표의 말이 하나도 안 걸렸다. 그런데 읽으면
번역투라고 지적받았다.

**아래 §자기 점검 4문항이 이걸 통과시킨다.** 1번 「이 말을 다른 데서 이 뜻으로
본 적 있나」는 조어를 잡는 검사다. `상속받다`·`표면`·`옹호`는 전부 흔한 말이고
흔한 뜻이라 통과한다. 걸려야 할 이유는 **그 자리에 한국어가 원래 쓰는 말이 따로
있다**는 것이다.

### 직역 어휘

| 쓰지 말 것 | 원어 | 대신 |
| --- | --- | --- |
| 결과를 상속받다 | inherit the consequences | **뒷감당하다** |
| 표면 / 표면적이 넓어진다 | surface area | **범위**, **손댈 곳** |
| 옹호하다 *(코드·결정을)* | defend the work | **설명하다**, **답하다** |
| A와 B 사이의 격차 | the gap between A and B | 두 문장으로 풀어 쓴다 |
| 확장이 안 된다 | doesn't scale | **못 늘린다**, **안 커진다** |
| 반감기가 온다 | half-life is one release | **값이 반으로 준다** |

`옹호`를 원뜻으로 쓰는 것은 정상 — *"그 정책을 옹호했다"* ○.

**출처가 자동번역이면 오역이 그대로 새어든다.** 위 실측에서 `삭았다`(decayed)가
자막에서 넘어왔다. 번역 자막을 근거로 쓸 때는 원어를 먼저 복원하고 시작한다.

### 압축이 서술어를 자르면 안 된다

아래 §caveman 표는 조사·헤지·접속사를 줄이라고 하는데 **서술어가 빠져 있었다.**
제일 잘라내기 쉬운 게 서술어라 실제로 잘려 나갔다.

```
✗ 해법은 검증 비용을 낮추고 건너뛰기 어렵게 만드는 것.
✓ 해법은 검증 비용을 낮추고 건너뛰기 어렵게 만드는 것이다.
✗ clean code의 수혜자가 "다음 에이전트"로 바뀜.
✓ clean code의 수혜자가 "다음 사람"에서 "다음 에이전트"로 바뀌었다.
✗ 압력 요인은 위임 길이.
✓ 위임 길이가 이걸 밀어붙인다.
```

한 문서 안에서 `~다` / `~것.` / `~뜻.` / `~바뀜.`이 섞이면 그것만으로 번역투로
읽힌다. **메모·체크리스트는 예외** — 거기서는 `~함` `~됨`이 정상이다.

### 콜론·화살표를 문장 라벨로 쓰지 않는다

§caveman 표의 「접속사 → `.` `:` `→` 치환」을 문장 앞머리에까지 적용하면 글이
아니라 표가 된다. 영어는 콜론 라벨이 문어체에 정착돼 있고 한국어는 아니다.

```
✗ Osmani의 경고 — taste가 마법의 단어로 쓰이는 걸 조심해야 한다
✓ Osmani는 taste가 마법의 단어로 쓰이는 걸 경고한다
✗ Mitchell Hashimoto의 더 쓸모 있는 정의: 객관적 지표가 없을 때…
✓ Mitchell Hashimoto가 더 쓸모 있게 정의했다. 객관적 지표가 없을 때…
```

치환해도 되는 접속사는 **문장 안**의 것이다 (`그래서`·`따라서`). 인물·개념을
앞세운 라벨은 문장으로 편다.

### 원어를 남기면 주변이 명사 구문이 된다

위 §그대로 써도 되는 것은 맞는 규칙이다. 다만 원어 명사를 박아 놓으면 한국어
동사가 안 붙는다 — `signature의 수명`, `taste가 남을 때만`, `high agency의
실제 뜻`. **원어 뒤에 서술어를 붙일 것.**

**외래어 뒤 조사는 띄우지 않는다.** `inner loop는` ○ / `inner loop 는` ✗.
2026-08-23 `~/.claude` 40곳이었고 이 파일 자신에도 있었다 (`jw가 직접 썼다`).

### 피동과 무생물 주어

```
✗ 역할이 재편된다              ✓ 역할이 일 중심으로 다시 짜인다
✗ 인지 대역폭은 병렬화되지 않는다   ✓ 내 머리는 병렬로 안 돌아간다
✗ 경계는 증거와 책임이다         ✓ 경계를 긋는 건 증거와 책임이다
```

## caveman 모드와의 관계

caveman 지침(`Drop articles/filler`, `Short synonyms`, `Fragments OK`)은
**영어 기준으로 쓰였다.** 한국어에 그대로 옮겨 적용하지 말 것.

> caveman이 조어의 원인은 **아니다.** 2026-08-13 측정: 압축이 더 센
> `full`의 조어율이 `lite`보다 오히려 낮았다 (1만자당 2.07 vs 5.57회).
> 원인이라면 방향이 반대여야 한다. caveman 이전 기록은 0자라 대조군
> 자체가 없다는 점도 같이 적어둔다 — 이 데이터로는 검증 불가다.
> 아래는 인과가 아니라 **예방 지침**이다.

**한국어에서 압축은 문장 구조에만 적용한다:**

- 압축 대상 — 군더더기, 헤지, 인사말, 중복 설명, 접속사
- **압축 대상 아님 — 어휘.** 단어를 줄이려고 새 말을 만들지 않는다

```
✗ 실격선: 모순 문서 회수 시 탈락
✓ 탈락 기준: 같은 질문에 서로 모순되는 문서가 검색되면 탈락
```

두 번째가 길지만 한 번에 읽힌다. 첫 번째는 짧지만 두 번 읽어야 한다.

### 무엇을 어떻게 줄이나

| 대상 | 처리 |
| --- | --- |
| **조사** (`은/는/이/가/을/를`) | 역할이 명확하면 생략. **모호해지면 유지** — 생략은 조건부다 |
| **헤지** | `~인 것 같습니다` `~일 수 있습니다` `~라고 볼 수 있습니다` `도움이 될 수 있습니다` → 단정하거나 뺀다 |
| **접속사** (`그래서/하지만/또한/그리고/따라서`) | `.` `:` `→`로 치환 |
| **반복 주어** | 같은 문단에서 두 번째부터 생략 |
| **기술 용어** (`렌더링` `커넥션 풀` `props` `커밋`) | **그대로 둔다.** 번역·축약 금지 |

마지막 줄이 이 문서의 요지다 — 줄이는 것은 문법 요소지 **용어가 아니다.**

*(조사·헤지·접속사 항목은 [cavemankorean](https://github.com/blacknabis/cavemankorean)
의 한국어 규칙에서 가져왔다. MIT. 플러그인은 설치하지 않았다 — 조어의 원인은
압축이 아니라 번역이라 도구가 필요한 문제가 아니다.)*

## 자기 점검

새 한자어 복합어를 쓰려는 순간 멈추고:

1. **이 말을 다른 데서 — 이 뜻으로 — 본 적 있나** — 없으면 내가 만든 것이다.
   `이 뜻으로`가 핵심이다. `배선`·`발화`·`회수`·`단언`은 전부 사전에 있고 다들
   쓰는 말이라 "본 적 있나"만 물으면 통과한다. 걸리는 이유는 **그 뜻이 다른
   분야 것**이기 때문이다 — 배선은 전기, 발화는 불과 언어학, 회수는 수거,
   단언은 논쟁. 읽는 쪽은 그 분야 뜻으로 먼저 읽고 멈춘다 (2026-08-20,
   194곳 중 4종이 이 검사를 통과했다)
2. **풀어 쓰면 몇 글자 늘어나나** — 열 글자 이내면 풀어 쓴다
3. **이미 여러 번 썼나** — 굳기 전에 바꾼다. 수백 회가 된 뒤엔 문서까지
   고쳐야 한다
4. **위 표에 있는 말에 접미사만 붙인 것 아닌가** — `수확`을 고친 그날
   `수확기`를 계속 썼다 (2026-08-14). 어근이 표에 있으면 `-기`·`-화`·`-성`·
   `-도`를 붙인 것도 같이 걸린다. **처리했다는 기억이 오히려 검사를 건너뛰게 한다**
5. **원어를 한국어 단어로 바꿨나** — 바꿨으면 그 자리에 한국어가 원래 쓰는 말이
   따로 있는지 본다. 1번은 조어만 잡아서 흔한 말·흔한 뜻이면 통과해 버린다
   (2026-08-23, `상속받다`·`표면`·`옹호`가 전부 통과했다)

**파일을 고쳤다고 끝이 아니다.** 같은 날 문서 8개에서 지운 말을 채팅에서 계속
썼다. 이 규칙은 한국어로 답할 때 적용되므로 대화가 오히려 주 대상이다 —
파일은 한 번 고치면 끝이지만 대화는 매 턴 다시 쓴다.

빈도 분석으로는 조어를 못 걸러낸다 (2026-08 시도, 실패). Claude 쪽 출력량이
훨씬 많고, 사용자 집계에는 Claude 문장을 인용·복사해 되물은 것이 섞인다.
**판정 기준은 "읽다가 걸리는가" 하나뿐이고 그건 사용자만 안다** — 지적받으면
위 표에 추가한다.
