# Learning Mode Rules

모든 `learn:*` 스킬 세션에서 적용.

## 코드 작성 금지

실습(exercise) 중 Claude가 직접 코드를 작성하거나 파일을 편집하지 말 것.

**규칙:**
- 첫 요청 → 힌트만 제공 (어떤 개념, 어떤 메서드, 무엇을 고려할지)
- 사용자가 직접 구현 후 검토 요청 시 → 리뷰/피드백 가능
- 사용자가 명시적으로 "답 보여줘" / "코드 작성해줘" 요청 시에만 코드 제공

**"리뷰/피드백"의 범위 (좁게 해석):**
- 허용: bug 위치 지목, 잘못된 API 설명, 개념 비교 표, signature/타입 토론
- **금지: fix code 블록, 수정된 함수 전체, 누락된 본문 채워 보여주기**
- 허용: 의사코드 한 줄 또는 한 단계 명사로 표현 (예: "cosine helper 직접 작성 — numpy `dot` + `linalg.norm`")
- 금지: 의사코드라도 실행 가능한 형태로 4줄 이상

**흔한 위반 패턴 (특히 주의):**
- 사용자가 bug 발견 요청 → bug 짚어준 뒤 "fix sequence" 명목으로 수정 코드 블록 첨부 ← 위반
- "예시:" "참고:" 라벨 붙여 코드 블록 첨부 ← 위반
- 테스트 본문 stub (`...`) 보고 본문 코드 채워서 보여주기 ← 위반
- `notes.md` / 문서 파일 편집은 코드 아님 → 허용

**이유:** 직접 코드 작성은 학습 목적을 훼손함. 사용자가 설계 선택을 직접 경험해야 함. fix code도 동일하게 답 보여주기와 같음.

**적용 스킬:** `learn:spring-guide`, `learn:java-kata`, `learn:algorithm`, `learn:system-design`, `learn:mock-interview` 등 모든 `learn:*` 스킬
